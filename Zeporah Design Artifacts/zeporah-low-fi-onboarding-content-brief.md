# Zeporah Low-Fidelity Onboarding Content Brief

This document provides the frame-by-frame content blueprint for the first 20 onboarding wireframes so they can be drawn consistently in low fidelity without inventing copy, hierarchy, or trust cues during layout work.[cite:9][cite:17][cite:26]

The brief is intentionally plain, calm, and operational. It is not polished marketing copy. Its purpose is to define what each wireframe frame should contain, what order information should appear in, and what the user should be able to do next.[cite:16][cite:17]

## Usage rules

Every frame should include a simple annotation panel beside the wireframe with the following fields: purpose, role, primary action, secondary actions, trust cues, and next screens.[cite:26]

Every onboarding frame should preserve the same product posture: private by default, explicit sharing, nonjudgmental language, and permission to stop and return later.[cite:9][cite:12][cite:16]

## LF-01 Welcome / direct entry

**Purpose:** Start the experience with calm clarity and explain the core value in one screen.[cite:17][cite:16]

**Frame structure:**
- Top utility area: Zeporah wordmark placeholder, Sign in link.[cite:17]
- Main headline: “A private place to organize what comes next.”[cite:17]
- Supporting text: one short paragraph explaining that Zeporah helps families keep track of tasks, information, and support after a loss or during serious family responsibilities.[cite:17][cite:16]
- Three value bullets: “Know what matters now,” “Share only what you choose,” “Come back whenever you are ready.”[cite:17][cite:9]
- Trust cue block: “Private by default. No organization, sponsor, or partner can see your family space unless you choose to send something.”[cite:9]
- Primary CTA: Create a private family space.[cite:9]
- Secondary CTA: Learn how privacy works.[cite:9]
- Tertiary text link: I already have an account.[cite:9]

**Interaction notes:**
- Primary CTA goes to LF-04 or LF-05 depending on whether privacy is shown before preferences in the chosen flow.[cite:9]
- Secondary CTA goes to LF-04.[cite:9]

## LF-02 Partner invitation landing

**Purpose:** Explain that the user arrived through an organization-related invitation without implying that the organization can access the workspace.[cite:9]

**Frame structure:**
- Header with back and Zeporah wordmark placeholder.[cite:9]
- Intro label: Invitation to use Zeporah.[cite:9]
- Main headline: “You were invited to use Zeporah with optional support connection.”[cite:9]
- Body copy: explain in simple terms that the invitation may make it easier to find help from the organization, but the family space remains private unless the user explicitly shares request information.[cite:9]
- Summary card: inviting organization name placeholder, what support route is available, what is not visible to them by default.[cite:9]
- Primary CTA: Continue.[cite:9]
- Secondary CTA: Use Zeporah privately for now.[cite:9]
- Link: Learn how privacy works.[cite:9]

**Trust cues:**
- “Your workspace is not visible to the organization by default.”[cite:9]
- “Support requests are reviewed before they are sent.”[cite:12][cite:9]

## LF-03 Family invitation landing

**Purpose:** Let an invited family member accept a role with a clear understanding of what access they will and will not receive.[cite:9]

**Frame structure:**
- Header with back and wordmark placeholder.[cite:9]
- Intro line: “[Inviter name] invited you to help in Zeporah.”[cite:9]
- Main headline: “Join this family space with clear access.”[cite:9]
- Role offer card: offered role, one-line explanation, visibility summary.[cite:9]
- Access card: “You will be able to…” and “You will not be able to…” columns.[cite:9]
- Primary CTA: Continue.[cite:9]
- Secondary CTA: Decline invitation.[cite:9]
- Link: Review privacy and access.[cite:9]

**Trust cues:**
- “You will only see what the coordinator chooses to share with you.”[cite:9]
- “Access can be changed later.”[cite:9]

## LF-04 Privacy overview

**Purpose:** Explain the trust model in under 20 seconds.[cite:9]

**Frame structure:**
- Header with back and progress indicator.[cite:9]
- Main headline: “Your family space is private by default.”[cite:9]
- Short paragraph: explain that tasks, notes, contacts, and documents stay inside the family space unless the user intentionally shares something.[cite:9][cite:12]
- Diagram block: You, People you invite, Organizations/support recipients, with simple arrows showing that nothing is sent automatically.[cite:9]
- Bullet list:
  - You choose who can see each part of the space.[cite:9]
  - Support requests show exactly what will be shared before you send them.[cite:12][cite:9]
  - You can change access later.[cite:9]
- Primary CTA: Continue.[cite:9]
- Secondary CTA: Read the full privacy summary.[cite:9]

**Frame structure:**

- Main headline: “Set this up in the way that feels easiest.”[cite:9]

- Secondary CTA: Skip for now.[cite:9]

## LF-08 What Zeporah can and cannot do

**Purpose:** Set safe expectations before setup continues.[cite:9][cite:17]

**Frame structure:**
- Header with back and progress indicator.[cite:9]
- Main headline: “What Zeporah can and cannot do.”[cite:17]
- Two-column comparison or stacked cards:
  - Can do: organize tasks, save key information, help coordinate with trusted people, show support options, let you request a connection.[cite:17][cite:9]
  - Cannot do: replace emergency help, provide legal/tax/medical advice, decide what should be shared, or contact someone without your approval.[cite:9][cite:12]
- Small emergency note block.[cite:12]
- Primary CTA: I understand, continue.[cite:9]

**Frame structure:**

- Main headline: “How would you like to begin?”[cite:9]
- Option card 1: Start a new family space.[cite:9]
- Option card 2: Join the space I was invited to, shown only if relevant.[cite:9]
- Short explainer under each option.[cite:9]

## LF-11 Minimal setup

- Header with back and progress indicator.[cite:9]

- Primary CTA: Continue.[cite:9]
- Secondary CTA: Skip optional questions.[cite:9]

**Purpose:** End onboarding with reassurance and direct the user into one manageable next step.[cite:17][cite:16]

**Frame structure:**
- Header with completion state, no dense celebration treatment.[cite:16]
- Main headline: “You have enough to begin.”[cite:16]
- Summary stack:
  - Your role.[cite:9]
  - Current stage.[cite:17]
  - Privacy default status.[cite:9]
  - Helper invitation status.[cite:9]
  - Support preference status.[cite:9]
- Reassurance text: “You do not need to finish everything today. Zeporah will help you start with one next step.”[cite:17][cite:16]
- Primary CTA: Go to my next step.[cite:17]
- Secondary CTA: Save and leave.[cite:9]
- Tertiary link: Review settings.[cite:9]

## Onboarding review checklist

The onboarding wireframes should be considered ready for broader board integration when the following are true.[cite:26][cite:9]

- All 20 onboarding frames exist.[cite:9]
- Each frame has one clear primary action.[cite:9][cite:16]
- Privacy is explained before any collaboration or partner-connected step.[cite:9]
- Role choice appears before collaboration-specific actions.[cite:9]
- The user is never forced to provide more information than needed to generate the first dashboard.[cite:17][cite:9]
- The language remains calm, plain, and nonjudgmental throughout.[cite:16][cite:17]
- Save-later or low-pressure exit paths exist where appropriate.[cite:9][cite:12]
